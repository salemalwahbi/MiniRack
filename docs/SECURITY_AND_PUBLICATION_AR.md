# إرشادات أمنية قبل رفع MiniRack على GitHub

**المجلد هذا للنشر بعد التنظيف، وليس نسخة إعدادات جهازك الشخصية.**

## لا تنشر أبدًا
- `include/wg_secrets.h` أو `include/wg_private_local.h` أو `src/minirack-bridge-secrets.h`.
- `include/minirack_v2_private.h`، أو ملفات `v2-device-private.json`, `v2-gateway-private.json`، أو حالة قاعدة بيانات الاشتراك/المفاتيح.
- كلمات مرور نقطة الوصول أو شبكات الفنادق/المنزل، ملفات `.env`، مفاتيح SSH، أو ملف تعريف IKEv2 `.mobileconfig`.
- صور تعرض QR إعداد VPN فعلي أو بيانات شبكة خاصة.

الأمثلة `.example.h` تحتوي قيمًا وهمية فقط، ويجب نسخها محليًا وتعبئتها دون رفعها.

## خطوات مراجعة قبل النشر العام
1. أنشئ مستودع GitHub **Private** أولًا.
2. راجع الملفات المجهزة وقاعدة `.gitignore`، ثم استخدم `git status --short` و`git ls-files` قبل أي push.
3. افحص تاريخ Git إن استخدمته مسبقًا؛ حذف السر من آخر Commit لا يحذفه من تاريخ قديم. لهذا الملف نوصي بإنشاء Git repo جديد من الحزمة الآمنة لا استخدام نسخة `.git` القديمة.
4. إذا كُشف مفتاح في أي مستودع Public يومًا، قم بتدويره؛ حذف الملف وحده لا يكفي.
5. قبل تحويل المستودع إلى Public، قرر أثر الكشف العلني على الملكية الفكرية/طلب براءة اختراع. النشر قد يؤثر على بعض الحقوق حسب الدولة.

## حدود الوصول
- خدمة Core التجريبية تستمع على localhost، والـrelay نطاقه WireGuard؛ لا تجعلها عامة على الإنترنت.
- نتائج المصادقة الحالية مراقبة (telemetry) ولا تطبق حظر NAT تلقائيًا؛ لا تصفها كتحكم وصول عالمي آمن مُعتمد.
- تطبيق سياسات حماية فعلية يحتاج اختبارًا على جميع المسارات.
